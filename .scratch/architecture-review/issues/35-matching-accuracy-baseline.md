**Category:** enhancement
**Summary:** Measure real matching accuracy once and calibrate the probability and skill-coverage bands from the result

**Why this cannot be delegated:** labels are the job seeker's own judgement of each vacancy. The runs call the paid decision model with the job seeker's credentials. Changing bands is a product decision. Vacancy text and the profile must stay private.

**Current behavior:**
The 0.2/0.8 probability bands and the ±10-point skill-coverage band are uncalibrated. The README says real accuracy has not been measured.

**Desired behavior:**
- Capture and label about 40 real vacancies in the workspace. Mix match, no-match and needs-clarification, and include criteria that are often unknown (advertised compensation, work location arrangement). Add a note to each label.

- Commit only aggregate numbers to the README's Matching section: agreement, the confusion matrix, the decision model identity and the matching rules version. Never commit vacancy text.
- Decide whether to change the bands. If they change, bump `MATCHING_RULES_VERSION`, re-run, and record the new aggregate next to the baseline.

**Acceptance criteria:**
- [ ] A labelled set of about 40 vacancies exists in the workspace.
- [ ] A baseline report exists, and its aggregate is in the README with the model identity and rules version.
- [ ] A band decision is recorded (kept or changed, with the reason). A change comes with a rules version bump and a second aggregate.

**Out of scope:**
- Building or changing the evaluation tool (issue 01).
- Re-labelling after every profile change.
- Comparing several decision models.
