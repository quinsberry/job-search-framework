# 14 — Include the decision model's identity in the criteria digest

Status: ready-for-agent
Type: task
Blocked by: 19
Spec: [decision-model-identity spec](../../decision-model-identity/spec.md)

`criteriaDigest` (`web/src/modules/applications/server/fingerprint.ts`) hashes `MATCHING_RULES_VERSION`, the target position, the skill threshold and normalised skills. It does not include which decision model judged the vacancies. Search memory prunes rejections only when this digest changes (or after 60 days), so switching the model (`typesafe/jev-1.14` today, hard-coded twice in `decision-model.ts`) or changing how the client encodes questions or maps scores, without remembering to bump `MATCHING_RULES_VERSION`, keeps rejections from the old model, and those vacancies are never re-judged by the new one.

Profile conversion already solves the same problem with provider cache identities.

Change:

- **Identity on the port.** Add `readonly identity: string` to the `DecisionModel` interface. `DecisionModelClient` builds a readable identity from:
  - a single model ID constant, which replaces both literals;
  - its input budget;
  - a client-local format version, bumped when the question encoding or the score mapping changes.
- **Digest input.** `criteriaDigest` takes the identity as a fourth argument. The composition root passes `model.identity` from the model it already builds. Test fakes provide a fixed identity.
- **What each version covers.** `MATCHING_RULES_VERSION` keeps covering matching only (structured checks, question text, bands and thresholds) and stays at `1`.
- **Docs.** In the README, split the "bump it when…" guidance into the two versions and say that a model change re-judges rejections. Add an amendment paragraph to ADR 0009.

Consequence accepted: the first run after this lands changes every digest, so all stored rejections are pruned and re-judged once, at model cost. Accepted vacancies are never pruned, so the application list is unaffected. Say so in the README and the commit. Issue 19's pinned digest is updated once, deliberately. The migration's fixed `ACCEPTED_DIGEST` does not change.

Done when changing only the model identity changes the digest, existing behaviour is otherwise unchanged, and tests, typecheck, lint and build pass.

## Agent Brief

**Category:** enhancement
**Summary:** Re-judge stored rejections when the decision model changes, by including the model's identity in the criteria digest

**Current behavior:**
Search memory stores each rejected vacancy with a digest of the criteria that judged it, and prunes rejections at run start when the current digest differs or after 60 days. The digest covers the matching rules version, the target position, the skill threshold and the normalised skills. It does not cover the decision model. Changing the model, its input budget, its question encoding or its score mapping leaves old rejections in place unless someone also bumps the matching rules version.

**Desired behavior:**
- The decision model port exposes a stable, readable `identity`. It changes whenever the model ID, the input budget or the client's question-encoding and score-mapping format version changes.
- The criteria digest includes that identity, so any of those changes prunes stored rejections on the next run and they are judged again. Accepted vacancies and the application list are unaffected.
- The production client's identity derives from one model ID constant, which is also the value sent in requests.
- The matching rules version still covers matching rules only and keeps its current value.
- The criteria digest of every existing workspace changes once. This is accepted, and is stated in the README and the commit.

**Key interfaces:**
- `DecisionModel`: gains `readonly identity: string`.
- `DecisionModelClient`: its identity is built from the model ID constant, its input budget and a client-local format version. Both request paths use the same model ID constant.
- `criteriaDigest(preferences, skills, rulesVersion, modelIdentity)`: a new fourth input. The search run's composition root passes the identity of the decision model it constructs.
- Test fakes of `DecisionModel` provide a fixed identity.
- The pinned criteria digest test from issue 19 is updated to the new literal in this change, with the reason stated.

**Acceptance criteria:**
- [ ] Changing only the model identity, with everything else equal, changes the criteria digest (unit test).
- [ ] The digest is still unaffected by budgets and skill order or spelling variants; the existing relative tests still pass.
- [ ] A run whose model identity differs from the one that judged a stored rejection prunes and re-judges that rejection, and never touches accepted vacancies (workflow test with fake models).
- [ ] The production client's identity changes when its model ID, input budget or format version changes, and the model ID appears once in the client.
- [ ] The README explains which version covers what, and that a decision model change re-judges stored rejections once, at model cost.
- [ ] ADR 0009 has an amendment saying that the digest includes the decision model's identity, and why.
- [ ] The pinned digest literal is updated once, with a comment or commit message explaining the deliberate change.
- [ ] Typecheck, lint, tests and build pass.

**Out of scope:**
- Comparing the model reported in a response against the requested one.
- Avoiding the one-off re-judge cost.
- Changing matching rules or bumping the matching rules version.
- Splitting the decision model port from its adapter (issue 10).
- The glossary, which is already updated.

### Implementation — 2026-10-24

- `DecisionModel` gains `readonly identity`. `DecisionModelClient` builds it as `typesafe/jev-1.14;input=28000;format=1` from `MODEL_ID` (now also used in both request paths), `MAX_INPUT_BYTES` and a new `FORMAT_VERSION`.
- `criteriaDigest` takes `modelIdentity` as a required fourth input; the run route passes `model.identity` from the client it constructs.
- Tests: the digest changes with only the identity changed; a workflow run under another identity re-judges the stored rejection but not the accepted vacancy, and the same identity skips it; the client's identity contains the model sent on the wire, the input budget and a format version. Fake models declare a fixed identity.
- The digest pin is updated to `b6384596…` (input now includes a fixed fake identity). Removing the identity from the digest fails three workflow tests.
- README (search workflow and model replacement) and an ADR 0009 amendment describe the versions and the one-off re-judge cost.
- `MATCHING_RULES_VERSION` is unchanged at 1. The v1 migration's `ACCEPTED_DIGEST` is untouched.
