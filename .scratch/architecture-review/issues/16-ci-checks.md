# 16 — Run typecheck, lint, tests and build automatically

Status: ready-for-agent
Type: task
Spec: [ci-checks spec](../../ci-checks/spec.md)

The web app's history (`next-migration`) has no CI workflow and no git hooks. `origin/main` still carries `.github/workflows/tests.yml` from the Python framework, which runs suites that no longer exist on `next-migration` and would fail once that branch merges. The ESLint boundary rules, their tests in `web/eslint.config.test.ts` and every check proposed in issues 17–21 only help if they run without someone remembering to.

Delete `tests.yml` and add `.github/workflows/web.yml` (workflow `web`, job `checks`) that, in `web/`, installs with Bun (`bun install --frozen-lockfile`) and runs `bunx tsc --noEmit`, `bun run lint`, `bun test` and `bun run build`, in that order, in one job.

The suite is already deterministic and offline (fictional workspaces, mocked AI, no live scraping), so it needs no secrets. The opt-in live checks from issues 01 and 04 must stay out of CI. The build still needs network for `next/font/google`; issue 29 covers self-hosting fonts.

Done when the workflow passes on the PR that merges `next-migration` into `main`, and a throwaway commit with a cross-module import turns it red on that PR (then reverted).

Decisions from grilling:

- Delete the Python `tests` workflow; add a new `web` workflow with job `checks` (check shows as `web / checks`).
- Triggers: push to `main`, every pull request, and `workflow_dispatch`. Push and pull-request runs skip changes that touch only non-code files (`**/*.md`, `.scratch/**`, `docs/**`, `LICENSE`); manual runs always run everything.

- Token permissions `contents: read`; concurrency grouped by ref, cancelling in progress for pull requests only; job timeout 15 minutes.

## Agent Brief

**Category:** enhancement
**Summary:** Replace the obsolete Python CI workflow with one that checks the Bun/Next.js web app

**Current behavior:**
The web app's branch has no CI. The default branch has a `tests` GitHub Actions workflow that runs the retired Python framework's suites, which do not exist in the web app's history and would fail after the merge.

**Desired behavior:**
- The Python `tests` workflow is gone.
- A GitHub Actions workflow named `web`, with a single job `checks`, runs in the web app directory:
  - frozen-lockfile Bun install;
  - TypeScript typecheck without emit;
  - lint;
  - the test suite;
  - the production build.
  Steps run in that order and stop at the first failure.
- It runs on pushes to `main`, on every pull request, and on manual dispatch.
- Push and pull-request runs skip the checks when the change touches only Markdown, `.scratch/`, `docs/` or `LICENSE`. Changes to the workflow itself, the web app, its lockfile or config always run them. Manual runs always run them.
- Bun's version comes from the web app manifest's `packageManager` field, and the Bun install cache is keyed on the lockfile.
- Token permissions are read-only for contents. A newer push to the same pull request cancels its older run, and runs on `main` are never cancelled. The job times out after 15 minutes.
- No secrets are used.

**Key interfaces:**
- Workflow `web`, job `checks`: the PR check name is `web / checks`.
- The web app's `packageManager` field (`bun@<version>`) is the single source of the Bun version.
- Non-code filter: trigger-level path ignores are acceptable unless the maintainer says `web / checks` is a required check. In that case, use an always-reporting filter step or job inside the workflow, so that docs-only PRs pass instead of staying pending.

**Acceptance criteria:**
- [ ] The Python `tests` workflow no longer exists.
- [ ] `web / checks` runs and passes on the pull request that merges the web app into `main`.
- [ ] A temporary commit on that PR adding a runtime import from one feature module into another makes `web / checks` fail at the lint step. The commit is then reverted and is not merged.
- [ ] A PR touching only Markdown or `.scratch/` files does not run the checks, and does not leave a pending required check.
- [ ] A manual dispatch runs all checks regardless of what changed.
- [ ] The workflow declares read-only contents permission, concurrency that cancels only pull-request runs, and a 15-minute timeout.

**Out of scope:**
- A pre-push hook (lefthook or similar).
- The opt-in live checks from issues 01 and 04.
- Self-hosting fonts so the build works offline (issue 29).
- Changing branch protection settings (a human step).
- Any change to the app's code, tests or lint rules.
