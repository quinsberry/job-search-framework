# 29 — Finish the Next.js app shell: metadata, error boundaries, leftovers

Status: needs-triage
Type: task

The app shell still carries create-next-app defaults and lacks error boundaries:

- `app/layout.tsx` metadata is `title: 'Create Next App'`, `description: 'Generated by create next app'`. Set a real title and description.
- There is no `app/error.tsx` or `app/global-error.tsx`. An uncaught render error in any section blanks the whole page. Add an `error.tsx` with a short message and a reset action, and consider a per-section boundary so a failure in Applications does not take down the profile and preferences editors. Drafts are already persisted on the server, so a reset loses at most the last 600 ms debounce window; say so in the boundary copy only if it is true at implementation time.
- `public/` still contains the template assets (`file.svg`, `globe.svg`, `next.svg`, `vercel.svg`, `window.svg`). Remove those that are unused (issue 21's knip check would also flag them).
- `next/font/google` (Geist, JetBrains Mono) fetches fonts at build/dev time; check that `bun run dev` and `bun run build` still work offline, since this is a local tool. If not, switch to `next/font/local` with committed font files.

Read the relevant guides in `node_modules/next/dist/docs/` first, as `web/AGENTS.md` requires for this Next.js version. Done when the items are addressed and typecheck, lint, tests and build pass.
