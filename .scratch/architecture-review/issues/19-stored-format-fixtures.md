# 19 — Golden fixtures for stored workspace formats and the cost-bearing keys

Status: ready-for-agent
Type: task
Spec: [stored-format-fixtures spec](../../stored-format-fixtures/spec.md)

Several upcoming refactors move or split the schemas that read users' workspace files (issues 03, 09, 11, 12). A mistake there either fails to read existing workspaces or changes a key that costs money: the criteria digest (a change prunes and re-judges every stored rejection at model cost) or the conversion cache key (a change pays for cached CV conversions again).

Existing tests build stored files inline and check the digest only relatively (same input, same digest), so a uniform change to either key or to a stored format can pass unnoticed.

Add committed fixtures, per module and next to its tests, with fictional data:

- `applications/applications.json` v2 and v3 (v1 is excluded; the v1 migration is due for removal, see issue 34);
- `candidate-profile/profile.yaml` and `draft.yaml`;
- `search-preferences/config.yaml` and `draft.yaml`;
- `search-runs/inspected.jsonl`.

Tests load each through the real repositories. The v2 file must load to the same content as the committed v3 fixture. Each current-format file must come back byte-for-byte after a load and a no-op save.

Pin `criteriaDigest` for a fixed input. The conversion cache key is already pinned by the legacy conversion cache test; add a cost comment there.

Done when the fixtures and tests exist and pass.

## Agent Brief

**Category:** enhancement
**Summary:** Lock stored workspace formats and the cost-bearing keys with committed golden fixtures

**Current behavior:**
Tests write stored workspace files from inline objects and assert the criteria digest only relatively. A refactor that changes how a stored file is read or written, or that changes the criteria digest or conversion cache key for every input, can pass the suite while breaking existing workspaces or causing paid re-work.

**Desired behavior:**
Committed fixture files, with fictional data only, exist for every stored format the app reads today:
- the applications list, schema versions 2 and 3;
- the candidate profile and its draft;
- the search preferences config and its draft;
- the search memory index.

Tests open each fixture through the real repository or store and check:
- The schema-version-2 applications list loads to the same content as the committed version-3 fixture.
- Every current-format fixture survives a load followed by a save of the unchanged values, with byte-identical output. If a writer is shown not to be deterministic, that one file is compared by parsed content instead, and the test says why.

`criteriaDigest(preferences, skills, rulesVersion)` is pinned as a literal for a fixed input, with a comment explaining that a change re-judges all stored rejections and must be deliberate. The conversion cache key is already pinned by an existing test; that assertion gets the matching cost comment.

**Key interfaces:**
- The repositories and stores that read and write each format: applications list, profile persistence, preferences repository, search memory. Use only their public load and save behaviour.
- `criteriaDigest`, tested directly. The conversion cache key is already pinned by the existing legacy conversion cache test (committed literal key, zero interpretations); export nothing new.
- Older fixtures are reconstructed from the schema as it stood in git history at the version's introduction, and each records its source commit.

**Acceptance criteria:**
- [ ] A fixture exists, per owning module, for each format listed above, with fictional data.
- [ ] A test proves the version-2 applications fixture loads equal to the version-3 fixture.
- [ ] A test per current-format fixture proves a no-op load and save leaves the bytes unchanged, or documents why parsed equality is used.
- [ ] A test pins the criteria digest to a literal for a fixed input, with the cost comment.
- [ ] The existing conversion cache key assertion carries the cost comment.
- [ ] Changing any stored-format schema, the digest computation or the cache key computation makes at least one of these tests fail.
- [ ] Typecheck, lint, tests and build pass.

**Out of scope:**
- Version-1 applications files, the pre-split workspace layout, and removing the v1 migration (issue 34).
- Edge-case fixtures (truncated lines, legacy fields, interrupted migration); they stay inline.
- Fixtures for conversion cache contents.
- Including the decision model's identity in the digest (issue 14).
- Any change to stored formats or key computations.
