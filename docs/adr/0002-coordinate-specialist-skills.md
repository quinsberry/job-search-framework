# Coordinate specialist skills through their contracts

The job-search lifecycle is coordinated by `jsf-workflow`, while focused specialist skills own domain work and persistent artifacts. The user chose this arrangement to make the full process convenient without reproducing specialist business rules in a large coordinator; orchestration selects operations, checks prerequisites and collects missing choices, then uses each owner's contract for data updates. Skills remain independently usable, and implementation proceeds one verified skill at a time.

Independent invocation requires valid inputs and declared prerequisites, without workflow or UI initialization. Shared validation and identity rules may be reused through explicit owner interfaces. Python implementations use namespaced packages to avoid ambient import state and standard-library name collisions; existing CLI entrypoints stay stable. Owners provide display summaries, identity sets and profile context so the coordinator does not interpret their internal history or source-registry containers. This preserves the six skill responsibilities and existing persisted formats; it does not require every skill folder to include its sibling dependencies.
