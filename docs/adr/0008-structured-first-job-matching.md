# Structured-first job matching with a swappable decision model

Search evaluates one vacancy against explicit preferences and profile skill strings. Structured checks run first and a confirmed failure avoids a model call; only unresolved role, seniority, position type, work arrangement, location and skill evidence goes to one injected `DecisionModel`. Its current implementation is Jev on OpenRouter, isolated inside `decision-model.ts`; matching neither imports Profile nor uses the profile-conversion AI providers.

Results retain criterion evidence: any failed criterion means `no-match`, otherwise unknown evidence means `needs-clarification`, otherwise `match`. Operational failures reject as errors. Model probabilities use inclusive 0.2/0.8 bands; accepted choice probabilities are summed and explicit unknown choices remain unresolved. Skill estimates use a ten-percentage-point band around the optional threshold; structured must-have coverage uses the exact threshold. Existing structured skill lists are treated as must-have until the source contract distinguishes optional skills.

Native advertised compensation is compared only in matching contract, currency and period units against baseline salary; targets and salary text do not establish requirements. Workplace location compares residence without inferring commuting or remote-country eligibility. Model input is bounded in UTF-8 bytes, reserving envelope space; truncation downgrades model-derived criteria to unknown rather than letting incomplete evidence establish a match. The future workflow owns acquisition, profile access, budgets and persistence, and must reject a configured skill threshold without profile skills before starting.
