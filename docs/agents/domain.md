# Domain docs

This repo uses one root `CONTEXT.md` for domain vocabulary and root `docs/adr/` for decisions. Create them when terms or decisions are resolved, not as empty placeholders.

Before exploring a feature, read `CONTEXT.md` and relevant ADRs if they exist. Use the glossary's terms in issues, specs, code, and tests. If a needed concept is missing, resolve its meaning through `/domain-modeling`. Surface any conflict with an existing ADR explicitly.
